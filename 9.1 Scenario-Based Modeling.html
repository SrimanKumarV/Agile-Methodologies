Scenario-Based Modeling,
through the College Canteen App

Every single day, the canteen queue eats into the next class's first ten minutes. The Principal has finally decided: build a Canteen Ordering App. But before anyone opens a code editor, that idea has to be turned into pictures everyone can agree on.

1 Starting Question

"Can the developer directly start coding?"

Every requirement modeling lesson can begin with this one question — and the canteen app is a perfect place to ask it.

The Story

The app should let students view the menu, order food, pay online, and collect food without standing in a queue. Simple enough to say out loud in one breath.

"Can the developer directly start coding?"

No.

Why not? Because the developer still doesn't know: who uses the system, what functions are actually needed, and how users will interact with it. To answer these three questions, one specific technique is used:

Scenario-Based Modeling

SPEC-00REQUIREMENT MODELING
PPT Definition
The process of identifying requirements that the software solution must meet, in order to be successful.
Easy Meaning
Before coding, requirements are converted into pictures, diagrams, and models — so that everyone understands the system the same way.

Requirement Modeling branches into four types. This guide covers the first one, in full detail.

2 Today's Topic, In Full

What is Scenario-Based Modeling?

One simple question sits underneath this entire topic.

SPEC-01SCENARIO-BASED MODELING
PPT Definition
A scenario that describes a thread of usage for a system.
Book Meaning
Represents the system from the user's point of view.
Easy Meaning
"Looking at the software through the user's eyes."
Ask Yourself

"If I am the user, how will I use this software?"

That single question is the entire mindset behind Scenario-Based Modeling. Everything in this chapter — the scenario, the actor, the use case, and every diagram — exists purely to answer it, piece by piece.

Scenario-Based Modeling itself is built from five components — each is its own part of this lesson.

3 Part 1

Scenario — the complete story of using the app

A scenario is simply the full journey of one user, told from beginning to end.

SPEC-02SCENARIO
PPT Definition
A scenario describes a thread of usage for a system.
Exam Definition
A Scenario is a specific sequence of actions that describes how users interact with the system.
Sequence of actionsUser interactionWorkflowStory of using the software
The Story — Raj is Hungry

Raj is hungry → opens the app → logs in → views the menu → orders a dosa → pays ₹40 → gets confirmation → collects food.

This entire journey — start to finish — is called a Scenario.

Real-life analogy: a movie has a beginning, a middle, and an ending. A scenario has exactly the same shape.

4 Part 2

Actor — WHO uses the system?

Once the scenario is clear, the next question is: which roles actually show up inside that story?

SPEC-03ACTOR
PPT Definition
Actor represents roles of people or devices in system functions.
Easy Meaning
Actor means: WHO uses the system?
Important Point
An actor is always outside the system.
Exam Definition
An Actor is anyone or anything that communicates with the system.
UserExternal EntityRoleOutside System Boundary
The Story

"Who uses our canteen app?"

Student · Canteen Staff · Principal · Payment Gateway

All four of these are Actors. Notice that "Payment Gateway" isn't a person — it's still an actor, because an actor is any role, person, or device that talks to the system.

5 Part 3

Use Case — WHAT does the system do?

If Actor answers "who," Use Case answers the other half of the question: "what."

SPEC-04USE CASE
PPT Definition
Use cases define what should be performed by the system.
Easy Meaning
Use Case means: WHAT does the system do?
Exam Definition
A Use Case describes how an actor uses the system to achieve a specific goal.
FunctionServiceGoalSystem Functionality
The Story

The student wants to:

Login · View Menu · Order Food · Pay · Track Order

Each one of these is a separate Use Case — a distinct thing the system lets an actor do.

7 Part 5

Preliminary Use Case — the first rough draft

Before writing anything formal, every use case starts life as a quick, rough sketch.

SPEC-06PRELIMINARY USE CASE
Guiding Questions
What to write? · How much to write? · How detailed should it be? · How should it be organized?
Easy Meaning
The first rough description — nothing fancy yet.
Example — Order Food, rough draft

1. Login → 2. Select Food → 3. Pay

Simple. Just enough to capture the idea — the detail comes later.

9 Part 7

Activity Diagram — a flowchart of the scenario

A use case diagram shows who and what. An activity diagram shows the actual order things happen in — including decisions.

SPEC-08ACTIVITY DIAGRAM
PPT Definition
Graphical representation of the flow of interaction within a specific scenario.
Easy Meaning
A flowchart of the scenario.
SymbolMeaning
Rounded RectangleActivity
ArrowFlow
DiamondDecision
Horizontal BarParallel Activities

10 Part 8

Swimlane Diagram — WHO does WHAT

The activity diagram shows the flow. The swimlane diagram adds one more layer — which actor owns each step.

SPEC-09SWIMLANE DIAGRAM
PPT Definition
Shows activity flow and indicates which actor is responsible for each activity.
Easy Meaning
Shows WHO does WHAT.
